# Запуск и обслуживание

Руководство для преподавателя, который разворачивает лабораторию на своём компьютере.

## Требования

- Docker Desktop либо Docker Engine с плагином Docker Compose.
- Интернет при первом запуске для загрузки образов и сборки.
- Для занятий в классе — локальная сеть, в которой компьютеры студентов могут подключиться к компьютеру преподавателя.
- В Windows — терминал WSL, имеющий доступ к Docker Desktop.

## Первый запуск

Из корня репозитория выполните:

```bash
./lab start
```

Если `.env` отсутствует, скрипт создаст его из `.env.example`. Затем Docker соберёт контейнеры и запустит приложение.

Откройте:

- Студенческая лаборатория: `http://localhost:8080`
- Панель преподавателя: `http://localhost:8080/teacher`

Для доступа из локальной сети укажите студентам IP-адрес компьютера преподавателя, например `http://192.168.1.20:8080`. Адрес `localhost` на компьютере студента указывает на сам компьютер студента.

`honey.test` встречается в учебном интерфейсе как часть примеров. Настраивать DNS, отдельный домен или файл `hosts` не нужно.

## Настройки

Параметры находятся в `.env` в корне проекта.

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `HTTP_PORT` | Порт сайта на компьютере преподавателя | `8080` |
| `BIND_ADDRESS` | Сетевой интерфейс, на котором открыт порт | `0.0.0.0` |
| `TEACHER_TOKEN` | Ключ доступа к панели преподавателя | `teacher-demo-key` |
| `DB_NAME` | Имя базы данных | `web_security_lab` |
| `DB_USER` | Пользователь PostgreSQL | `web_security_lab` |
| `DB_PASSWORD` | Пароль PostgreSQL | Значение из `.env.example` |

Перед занятием замените `TEACHER_TOKEN` и `DB_PASSWORD` на свои значения. Для занятия только на одном компьютере установите `BIND_ADDRESS=127.0.0.1`.

Изменение `DB_PASSWORD` в `.env` не меняет пароль уже созданной роли PostgreSQL. Значения `DB_NAME` и `DB_USER` также применяются при первоначальном создании базы.

## Подключение класса

1. Узнайте локальный IPv4-адрес компьютера преподавателя.
2. Проверьте, что `BIND_ADDRESS=0.0.0.0`.
3. Разрешите входящие подключения к `HTTP_PORT` в брандмауэре компьютера преподавателя.
4. Убедитесь, что студенческие устройства находятся в доступной сети. Гостевая Wi-Fi-сеть с изоляцией клиентов может блокировать подключение.
5. Откройте `/teacher` именно по LAN-адресу, например `http://192.168.1.20:8080/teacher`. Тогда скопированный из панели адрес будет подходить студентам.
6. Введите `TEACHER_TOKEN` вручную. Панель не получает секрет автоматически.

Автоопределения сетевого IP в приложении нет. Если открыть `/teacher` через `localhost`, адрес для класса также будет содержать `localhost`.

## Команды стенда

Выполняйте их из корня репозитория:

```bash
./lab start    # собрать и запустить контейнеры
./lab status   # показать состояние контейнеров
./lab logs     # смотреть журналы; Ctrl+C завершает просмотр
./lab stop     # остановить контейнеры, сохранив данные
./lab reset    # удалить данные PostgreSQL и создать стенд заново
```

`./lab reset` удаляет Docker-том базы без дополнительного подтверждения. Будут удалены участники, история запросов и прогресс всей группы. Кнопка «Сбросить занятие» в панели тоже сбрасывает данные группы, но запрашивает подтверждение.

## Участие студента

1. Откройте адрес преподавателя и зарегистрируйтесь с именем и группой.
2. Выберите дело в боковой панели и ознакомьтесь с целью.
3. Исследуйте магазин и его обычные ответы.
4. Выберите действие в журнале трафика и откройте запрос в перехватчике.
5. Измените запрос, отправьте его и сравните результат.
6. В отчёте объясните причину, влияние и способ исправления.

В перехватчике заголовки и тело задаются JSON-объектами. Пустой объект — `{}`, не `[]`. Для GET оставляйте тело `{}`. В поле пути указывайте путь и параметры, например `/api/catalog?filter=honey`; HTTP-метод выбирается отдельно.

Учебные запросы идут через интерфейс лаборатории. Их не нужно открывать в адресной строке.

## Сессии и сохранение прогресса

Сессия связана с cookie браузера и действует 8 часов. Повторная регистрация создаёт новую запись, даже если указать то же имя. Для продолжения используйте тот же браузер и не выходите из сессии.

История и прогресс хранятся в PostgreSQL. `./lab stop` сохраняет базу. Полный сброс удаляет её содержимое.

## Решение проблем

| Симптом | Что проверить |
|---|---|
| `Permission denied` при запуске | Выполнить `sh ./lab start` из корня проекта |
| Docker недоступен | Запустить Docker Desktop или службу Docker Engine |
| Порт занят | Изменить `HTTP_PORT` в `.env`, затем выполнить `./lab start` |
| Студентам сайт недоступен | LAN-IP, `BIND_ADDRESS`, брандмауэр и изоляцию Wi-Fi-клиентов |
| Страница не обновилась после сборки | Дождаться завершения запуска и обновить страницу без кеша |
| Панель показывает ошибку обновления | Проверить `./lab status`, затем `./lab logs` |
| Зачёт не появился | Проверить шаги цепочки, метод, путь, JSON и режим отправки |
| После входа прогресс пуст | Возможно, создана новая сессия; имя не восстанавливает прежний прогресс |

При повторяющейся проблеме сохраните журналы `./lab logs` до остановки стенда и опишите шаги, после которых возникла ошибка.
