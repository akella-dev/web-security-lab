Web Security Lab — локальная лаборатория для занятий по безопасной разработке и тестированию веб-приложений. Студенты исследуют учебный интернет-магазин, изучают реальные HTTP-запросы и проверяют, как сервер реагирует на их изменения. Преподаватель видит ход занятия и прогресс группы.

Стенд рассчитан на компьютерный класс: преподаватель запускает его на одном компьютере, а студенты подключаются к нему из браузеров в общей локальной сети.

## Что внутри

- **16 сценариев** по валидации данных, контролю доступа, XSS, SQL-инъекциям, аутентификации, SSRF, JWT и состоянию гонки.
- **Учебный магазин** с профилем, корзиной, поиском, отзывами, поддержкой и служебными разделами.
- **Журнал трафика и перехватчик запросов**: можно изучить отправленный запрос, изменить его и сравнить ответы.
- **Пошаговые расследования**: дополнительные материалы открываются по мере выполнения предыдущих этапов.
- **Панель преподавателя** с участниками, прогрессом и последними событиями.
- **База знаний** без готовых решений и отдельное руководство для преподавателя.

## Быстрый запуск

Нужен Docker Desktop либо Docker Engine с Docker Compose. При первом запуске Docker скачает образы и зависимости. Откройте локальный клон репозитория в терминале и выполните:

```bash
./lab start
```

Скрипт создаст `.env` из `.env.example`, если файла ещё нет, соберёт контейнеры и выведет адреса.

- На компьютере преподавателя: [http://localhost:8080](http://localhost:8080)
- Панель преподавателя: [http://localhost:8080/teacher](http://localhost:8080/teacher)
- Для студентов: `http://<IP-компьютера-преподавателя>:8080`

Для подключения класса компьютеры должны видеть друг друга в локальной сети. Разрешите входящие подключения к выбранному порту в брандмауэре. Подробности и настройки — в [руководстве по запуску](docs/GETTING_STARTED.md).

## Как проходит расследование

1. Студент выбирает дело и читает его цель.
2. Выполняет обычное действие в магазине, например оформляет заказ.
3. Находит запрос в журнале трафика и изучает его в перехватчике.
4. Меняет один параметр и сравнивает ответ сервера с исходным.
5. Объясняет причину проблемы, её последствия и возможное исправление.

Учебные API-пути вводятся в перехватчике. Это виртуальные маршруты симулятора, а не отдельные адреса для открытия в браузере.

## Программа

| Глава | Темы |
|---|---|
| Покупатель с вопросами | Подмена цены, отрицательное количество, раскрытие диагностических сведений |
| За дверью кабинета | Mass assignment, IDOR, доступ по скрытому адресу, повышение привилегий |
| Когда текст становится кодом | Отражённый XSS, сохранённый XSS, SQL-инъекция |
| Чужая личность | Перечисление пользователей, предсказуемый токен, обход MFA |
| За пределами витрины | Гонка купона, SSRF, подмена JWT |

## Безопасное использование

Проект намеренно моделирует уязвимости. Он создан для локального обучения и не предназначен для публикации в интернете. Не открывайте порт стенда во внешнюю сеть и не используйте реальные персональные данные или секреты. SSRF, SQL-инъекции и другие сценарии воспроизводятся внутри модели и не обращаются к произвольной внешней инфраструктуре.

Перед занятием замените демонстрационные `TEACHER_TOKEN` и `DB_PASSWORD` в `.env`. Ключ преподавателя не сообщайте студентам.
