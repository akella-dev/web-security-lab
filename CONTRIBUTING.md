# Участие в проекте

Спасибо за интерес к Web Security Lab. Это учебный симулятор уязвимостей; изменения должны сохранять изоляцию сценариев и соответствие между интерфейсом, сервером и материалами занятия.

## Локальная разработка

Нужны Docker Compose для полного стенда либо локальные Node.js/npm и PHP с Composer для отдельной части.

### Интерфейс

```bash
cd frontend
npm ci
npm run dev
```

Доступные команды:

```bash
npm run check     # тесты, проверка TypeScript и lint
npm run build     # production-сборка
```

### API

Из каталога `api/`:

```bash
composer install
composer qa
```

Для интеграции API с PostgreSQL задайте параметры подключения из `.env` и запустите базу через Compose.

### Полный стенд

Из корня проекта:

```bash
./lab start
./lab logs
./lab stop
```

## Где менять поведение

- Новые или изменённые задания: `api/src/Domain/Lab/`.
- Условия распознавания: `api/src/Domain/Lab/ExerciseEngine.php`.
- Сюжетные названия и порядок дел: `frontend/src/lib/campaign.ts`.
- Запросы и журнал интерфейса: `frontend/src/components/StudentLab.tsx`.
- Панель преподавателя: `frontend/src/components/TeacherDashboard.tsx`.
- Документация: `README.md`, `docs/` и этот файл.

При изменении задания согласуйте идентификаторы, критерии зачёта, подсказки, этапы и ключ преподавателя. Описание должно точно соответствовать смоделированному поведению.

## Принципы изменений

- Не отправляйте запросы сценариев во внешнюю сеть и не добавляйте реальные секреты.
- Сохраняйте изоляцию данных студентов.
- Объясняйте и штатный, и ошибочный путь.
- Обновляйте документы вместе с изменением поведения.
- Не включайте в публичные примеры реальные персональные данные.

Перед отправкой изменений выполните подходящие проверки `npm run check`, `npm run build` и `composer qa` для затронутых частей. В описании изменения укажите, что поменялось и какие проверки были выполнены.
